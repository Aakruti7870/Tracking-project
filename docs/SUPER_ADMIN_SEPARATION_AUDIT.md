## Authorization findings

1. **Resolved:** reusable Play-review Authority access crossed the intended privilege boundary. Authority is no longer a reviewer role; Customer, Plant Owner and Driver reviewer fixtures remain.
2. **Resolved:** Central Admin is isolated from legacy operational routers even where old RBAC lists still mention `central_admin`; authenticated Central Admin requests are fail-closed to dedicated Control Center/admin routes.
3. **Resolved:** Authority is not conflated with Central Admin. Authority remains an operational Plant Staff email/MFA role.
4. **Resolved:** startup permanent-platform provisioning no longer rewrites a conflicting existing account's primary role.
5. **Resolved:** Central Admin first-time/recovery MFA bootstrap cannot be promoted into a privileged web session. Enrollment ends the bootstrap and requires dedicated TOTP sign-in again.
6. **Resolved:** restricted additional Central Admins do not inherit full read/mutation access; explicit permission grants are enforced server-side.
7. **Resolved:** Control Center session revocation is constrained to current Central Admin session owners and cannot target Customer, Driver, Owner, Authority or other Plant Staff sessions.
8. **Known architectural follow-up, not a bypass in this PR:** Control Center bearer tokens remain in JavaScript runtime memory rather than `localStorage`/`sessionStorage`. A future backend-managed HttpOnly/Secure/SameSite cookie + CSRF design may further improve browser-session hardening.
9. **Planned, not falsely presented as live:** Login / OTP administration, device inventory, security alerts and other unsupported modules remain disabled until dedicated permission-gated backend contracts exist.
