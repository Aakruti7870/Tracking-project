## Authorization findings

1. **Resolved:** reusable Play-review Authority access crossed the intended privilege boundary. Authority is no longer a reviewer role.
2. **Resolved:** public Expo contained direct privileged route modules, not merely hidden links. Those modules are deleted.
3. **Resolved:** shared owner subscription UI compiled Authority-only offline/free activation and promo-code mutations. Those branches are deleted from mobile.
4. **Open:** startup code permanently creates/promotes two support Authority emails. It uses normal MFA rather than fixed OTP, but automatic permanent elevation should be replaced by an audited invite/approval process after production ownership is verified.
5. **Open:** existing backend sessions use bearer tokens. The portal deliberately keeps its short-lived token only in JavaScript memory (never `localStorage`/`sessionStorage`). A future backend-managed HttpOnly/Secure/SameSite cookie plus CSRF implementation is preferable before broad production rollout.
6. **Open:** existing privileged endpoints audit many mutations but do not uniformly require the new five-minute `admin_step_up_at` marker. No destructive functions were added; wire the marker into each selected high-risk backend mutation in a focused follow-up.
